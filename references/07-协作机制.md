# 07 · 协作机制：一个控制面，一根接力棒，两个模型

> 目标：让 2–5 个人 + 若干 Agent 在 24–72 小时里不互相踩，换人不丢上下文。
> 来源：`project-flow` 的 flow/docs 分层、进展接力棒、分层入口、跨模型评审、收工自检 hook、文档维护 SOP；按比赛节奏压缩，并加了两栏字段与一条 F 点约束；2026-10 补分布式/兼职团队一节（外部实证吸收）。

---

## 一、三层归属

| 层 | 目录 | 放什么 | 谁读 |
|---|---|---|---|
| **控制层** | `flow/` | charter、team、未认领、plan、claims、assumptions、进展、decisions、踩坑、tasks、`规范/` | 所有 Agent 开工必读 |
| **内容层** | `docs/` | `product/` `architecture/` `contracts/` `modules/` `reviews/` | 评委、下一棒、自己回看 |
| **代码层** | `web/` `api/` `android/` … | 能跑的东西 + 各自的 `AGENTS.md` | 机器 + 该模块的人 |

**R1 归属判据（改版）**：

- 决定"要不要继续 / 先做哪个" → `flow/`
- 决定"做出来的东西对不对" → `docs/`
- 是"能跑的东西" → 模块目录
- 一篇文档同时被两层需要 → 放 `docs/`，`flow/` 里只放指针

**铁律：同一个事实只写一遍。** 复制就会漂移，24 小时里漂移没人有空修。

## 二、进展日志 = 交接棒

`flow/进展.md`，**append，新的放最上面，顶部那条就是当前交接棒**。

### 为什么是一个 append 文件，而不是一堆卡

| 方案 | 问题 |
|---|---|
| 每人一张卡 | 会堆爆，且不知道哪张是最新的 |
| 每次覆盖快照 | 丢历史，没法复制给别的 Agent |
| **append 一个文件** | 留历史 + 不爆 + 顶部即棒 |

### 字段（比原版多两栏）

```markdown
## 2026-10-27 03:20 · 事件查询打通 · 甲

- **做了什么**：实现 search_events 与 get_event，接上契约样例
- **为什么这么做**：契约冻结里 C01/C02 是硬断言，先保住这两条
- **产出（路径）**：`api/events.py`、`flow/claims.md` C01/C02 已标通过
- **状态**：局部实测                        ★新增
- **问题 → 怎么解决**：时间字段用了本地时区，改成 UTC 后对齐
- **未决事项（待拍板）**：语义检索的 embedding 维度还没定，先按 1024 占位   ★新增
- **下一步（接手方第一个动作）**：跑 `scripts/check.sh` 确认 C01–C04
```

### 新增两栏的理由

**`状态`**：不写状态，下一个人不知道能不能在它上面继续搭。用六分类，不用"已完成"（见 `SKILL.md` 铁律③）。

**`未决事项（待拍板）`** 而不是"下一步"：写成"下一步"，接手方会自行推进；写成"未决事项"，它会停下来问。**24 小时里越权推进比不推进更贵**——一个人按错误假设往前走了三小时，回头要重做六小时。

### 铁律：只带「指针 + 增量」

产出给真实路径，不重抄内容。接手方要细节就顺指针回源文件读。

**同时贴回对话**：用户当场看到，也能直接复制给另一个 Agent。

## 二·补、聊天内容怎么过河：五种落点 + 一个不存

**先接受一个事实：两个 Agent 之间没有对话通道。** A 的上下文 B 完全看不见——你在 A 那边说的"我们决定不做登录"，B 一个字都读不到。**唯一的传递介质是文件**（加上你手动复制粘贴）。

所以"聊天内容存哪"不是存不存的问题，是**拆成五种，各落一个文件**：

| 聊天里出现的东西 | 落到哪 | 存法 |
|---|---|---|
| 这一棒的结论 | `进展.md` 顶部条 | 摘要 3–5 行 |
| 拍板了的选择 + 否决掉的方案 | `decisions.md` | 「决定 / 否决的方案 & 原因」 |
| 试了不行的方法 | `踩坑记录.md` | 重点写**为什么不行** |
| "我猜 / 应该是 / 大概" | `assumptions.md` | 一句话 + 置信度四级 |
| **主办方 / 评委 / 用户的原话** | 对应文件 | **原文引用 + 出处**（唯一需要原文的场合） |
| 代码、文档、表格 | `docs/` 或代码目录 | **不存内容，只给路径** |
| 闲聊、反复确认、中间试错 | — | **不存** |

### 为什么聊天原文不存

一场 24 小时的对话，原文几万字。下一个 Agent 不会读完，读完了也抓不到重点——**它需要的是"现在在哪 + 为什么这么定"，不是"我们怎么聊过来的"**。

真正会丢的不是"说过什么"，而是**"为什么否决了方案 B"**。这一句必须落 `decisions.md`，否则下一棒会花两小时重新试一遍 B。

### 五个必写触发器（不写就丢）

| 触发 | 写哪 |
|---|---|
| 用户说"就这样 / 定了 / 开始做" | `decisions.md` 一条 |
| 试了一个方向但放弃 | `踩坑记录.md` 一条（**写清死路**） |
| 换 Agent / 换模型 / 换人 | `进展.md` 顶部一条 |
| 每过一道门（G1–G4） | `进展.md` 顶部一条 |
| 出现"我猜 / 应该是" | `assumptions.md` 一条 |

### 交接的标准动作（三步）

```
A 收工：写进展.md 顶部条 → 把这一条整条贴回对话
              ↓  用户复制
B 开工：读 AGENTS.md → 读进展.md 顶部那条 → 顺指针读必要文件
              ↓
B 的第一句话：复述三件事（当前状态 / 下一步第一个动作 / 未决事项）
```

**为什么要它复述**：复述是唯一能验证"它真的读到了"的办法。复述不对，说明**文件写得不够**——去改文件，不要靠口头补。

**开工咒语**（直接复制给下一个 Agent）：

> 读 `AGENTS.md` 和 `flow/进展.md` 顶部那条。然后只回答三件事：① 现在在哪一步 ② 下一步第一个动作是什么 ③ 有哪些未决事项需要我拍板。**先不要动手。**

### 多个 Agent 并行时按目录分工

| 做法 | 结果 |
|---|---|
| 按功能分工（"你写后端、我写前端"） | 两个人改同一个契约文件，冲突 |
| **按目录分工**（"你只改 `api/`，我只改 `web/`"） | 冲突降到最低，契约在 `docs/contracts/` 单独管 |
| 一个 Agent 干完另一个接着干 | 必须有交接棒，否则重复劳动 |

## 三、分层入口：根级一份，模块各一份

| 文件 | 谁生成 | 写什么 | 不写什么 |
|---|---|---|---|
| 根级 `AGENTS.md` | T-22 | 项目一句话、目录地图、铁律、**现在在哪**、指针 | 不写具体任务、不写计划 |
| 根级 `CLAUDE.md` | T-22 | 指向 `AGENTS.md` | — |
| 模块级 `AGENTS.md` | **G1 之后**（模块目录建出来时） | 本模块职责、怎么跑、不许做什么、指回根级 | **不另起计划** |
| 模块级 `CLAUDE.md` | 同上 | 指向本模块 `AGENTS.md` | — |

模板：`assets/AGENTS.md`（根级）、`assets/MODULE_AGENTS.md`（模块级）

**软链规则**：类 Unix 用软链 `ln -s AGENTS.md CLAUDE.md`；**Windows 直接复制**（软链要管理员权限，现场别赌）。复制之后两份会漂移，所以定一条：**只改 `AGENTS.md`，改完立刻 `cp AGENTS.md CLAUDE.md`**。

**判据**：一个全新 Agent 进来，只读根级 `AGENTS.md` + `flow/进展.md` 顶部，能不能直接开工？能 → 合同合格。

### 根级 AGENTS.md 最小骨架

```markdown
# <项目名>

一句话：<给谁解决什么问题>

## 现在在哪
阶段：S4 构建 / 已过 G2，契约冻结在 docs/architecture/契约冻结.md
交接棒：读 flow/进展.md 顶部
F 点：<日期 时间>，之后只修不加

## 目录
flow/       控制层（charter / plan / claims / 进展）
docs/       内容层（product / architecture / contracts / modules / reviews）
web/ api/   模块（各自有 AGENTS.md，只在需要时读它）

## 铁律
1. F 点之后只修不加
2. 状态只写 未见实现 / 代码已有 / 局部实测 / 报告待验证 / 完整验收 / 方向待定
3. 契约在 docs/contracts/，改要先写 flow/decisions.md
4. 验收看 flow/claims.md，不看"感觉"
```

## 四、多人与多 Agent 并行

### 分工按"目录 + 主责人"，不按"功能名"

| ✅ 好分工 | ❌ 坏分工 |
|---|---|
| 甲：`api/` 全部 | 甲：接口 |
| 乙：`android/` 全部 | 乙：界面 |
| 丙：`ml/` 全部 | 丙：算法 |

按功能分，两个人会在同一个文件里相遇；按目录分，冲突面积最小。

### 每个包只有一个主责

"前端组负责"这种写法等于没人负责。工作包卡的"主责"必须是一个人。

### Agent 并行时的冲突处理

| 情况 | 做法 |
|---|---|
| 两个 Agent 改同一文件 | 串行，后一个先读前一个的产出 |
| 一个 Agent 改契约 | 停下来，先写 `flow/decisions.md`，人工确认 |
| Agent 报"已完成" | 要求它给状态六分类 + 断言结果，否则不认 |

**如果 push 一次要很久，就别用分支协作，改同机开发。** 工具链按真实成本算，不按最佳实践。

### 分布式 / 兼职团队：不是所有人都能 24 小时在线

跨校、跨公司、有人只能晚上和周末干活的队，"每 3 小时同步"直接失效。换一套：

| 机制 | 具体做法 | 为什么 |
|---|---|---|
| **每日 15 分钟文字站会** | 固定时间，每人只报两条：**可运行成果**（一个路径或一条命令）+ **阻塞**（卡在什么、要谁决策） | 兼职的人没法全天待命，异步是唯一可行的；报成果不报心情——没有可运行成果就是没有进度 |
| **阻塞 24h 升级线** | 阻塞超过 24 小时没解，自动升级队长，升级时**必须带裁剪方案**（砍哪块、保哪块） | 兼职队员不好意思催，队长信息滞后一天，整个里程碑歪一天 |
| **容量假设明示** | 排期前每人写下"我本周能投几小时"，写进 `flow/team.md` | 不写就按满勤排，第三天发现一半工时不存在 |
| **里程碑不后移，只砍范围** | 到点没完成，砍范围保日期，不顺延排期 | 比赛截止是硬墙，顺延一次就会顺延第二次 |
| **排期用绝对日期** | "10 月 12 日前交契约"，不写"D+3" | 兼职队员的 D 不是同一天开始的 |

**判据：一个只在周末出现的人，能不能靠文件接上棒？** 不能 → `flow/进展.md` 写得不够细，去改文件，不要指望他口头问。

## 四·补、情绪：24 小时里没有冷战的位置

**这条来自两支没获奖的队伍，不是冠军。** 冠军复盘里几乎不提冲突——因为赢了，冲突就被叙事抹平了。一位人文背景参赛者的原话：

> 「24 小时限制，迫使我们即使有分歧也要迅速找出解决方案。否则，我们可能会先冷战 24 小时。」

### 4.1 先算账，再谈感受

冷战 1 小时 = 4 人 × 1 小时 = **4 人时**，且这 4 小时主链路零推进。冷战到天亮 = 比赛结束。

**这不是情绪问题，是算账问题。** 把这句话讲给队友听，比说"我们别吵了"有效得多。

### 4.2 机制的四个动作（写进 `team.md`）

| 动作 | 具体做法 |
|---|---|
| **分歧限时变形** | 10 分钟内必须变成"两条可验证的方案"，不能停在"我觉得 A 好" |
| **谁提谁验证** | 提出方案的人给出验证方式和时间盒（15 / 30 分钟），不是让全队一起讨论 |
| **到点拍板** | 时间盒到，按当前最好的证据定；输的一方**保留意见但不重复讨论**，在 `decisions.md` 里注明谁不同意 |
| **合法暂停** | 允许说"我现在情绪上头，20 分钟后再谈"——这是唯一合法的暂停，但必须给出回来的具体时间 |

### 4.3 一条判据

> **"说服队友"的成本，通常高于"验证一次"的成本。**

争 20 分钟谁对，不如花 10 分钟跑一次。**24 小时里，能跑的都去跑，别争。**

### 4.4 三个前兆（出现了就按上面四条办）

- 同一个问题第 3 次被提起，且措辞越来越短
- 有人开始说"随便吧"/"你们定"
- 讨论从"哪个对"变成"你上次也这样"

## 五、跨模型评审

**审稿模型 ≠ 产出模型。** 错误不相关，等于免费质量倍增。

| 时机 | 模式 | 产出 |
|---|---|---|
| 每次里程碑 | 生成 → 评审 | PASS / FAIL + 理由 |
| 高风险逻辑 | 对抗找茬 | 问题清单 |
| 设计岔路 | 第二意见 | 两个方案的取舍表 |

结论写进 `docs/reviews/`，一行一条，带日期和模型名。

### 不要问"你觉得怎么样"

那种问法只会得到客套。用这个模板：

```
只回答三件事，不要给建议：
1. 哪个结论你无法从材料里确认？（指出具体位置）
2. 哪个数字没有来源或边界说明？
3. 如果我是评委，我会追问什么？
```

第三个问题最有价值——**它直接产出你要准备的答辩答案**。

## 六、收工自检 hook（有实体，但本机不生效）

`project-flow` 用 Stop hook 在每回合结束时检查文档与交接。这里给**完整的可安装实体**，不只是一句"建议"。

### 三份文件（复制到项目根）

```
.hooks/stop-doccheck.sh        脚本本体
.claude/settings.json          Claude Code 的 Stop 配置
.codex/hooks.json              Codex 的 Stop 配置
```

脚本逻辑：每回合结束读 stdin 的 JSON → 取 `session_id` + 本回合 ID（Claude 用 `prompt_id`、Codex 用 `turn_id`）→ 用 `/tmp` 标记目录保证同一回合只触发一次 → 输出 `{"decision":"block","reason":"..."}` 让 Agent 续跑一次自检。

**任何一个前提不满足就静默放行**（`{"continue":true}`），不阻塞：
- 没有 `jq`
- 拿不到 session_id 或回合 ID（更旧版本的 Codex）
- 已经是 hook 触发的续跑（`stop_hook_active`）

### 黑客松版的自检文案

```bash
reason="【收工自检】① 状态：本轮改过的模块，flow/claims.md 里对应断言跑了吗？没跑就写「代码已有」，不许写「完整验收」。② 交接：在 flow/进展.md 顶部追加一条（做了什么/为什么/产出路径/状态/未决事项/下一步），并把这条贴在回复里。③ 决策与坑：改过契约或范围 → flow/decisions.md；踩过坑 → flow/踩坑记录.md。④ 若已过 F 点，本轮只许修不许加功能。都没涉及就回复「无需更新」。"
```

### 装之前先知道这两件事

| 事实 | 后果 |
|---|---|
| **本机没有 `jq`**（已实测） | 脚本会在第一道检查处静默放行，**等于没装**。要生效先 `winget install jqlang.jq` |
| 现场环境不一定装得上 | 装一个半失效的 hook 比没有更糟——它让你以为有保护 |

**24 小时的正确用法**：赛前在自己机器上装好并验证一次（改一个文件 → 看它有没有 block）；现场如果换机器，改用**手工清单**：

```
每小时同步时问三句：
- 进展条写了吗？
- 状态写的是六分类里的哪个？
- 有没有没写进「未决事项」的岔路？
```

> **判据：能用但会静默失效的东西，必须在别处有兜底。** hook 的兜底就是上面这三句。

安装：

```bash
mkdir -p .hooks .claude .codex
cp <skill>/assets/.hooks/stop-doccheck.sh .hooks/
cp <skill>/assets/.claude/settings.json .claude/
cp <skill>/assets/.codex/hooks.json .codex/
chmod +x .hooks/stop-doccheck.sh
# Codex 侧还需在 /hooks 里批准，并把项目 trust
```

## 七、文档维护：`docs/README.md` 是索引

`project-flow` 的文档维护 SOP 在比赛里裁到只剩两条，但这两条不能省：

| 规则 | 为什么 |
|---|---|
| **`docs/README.md` 必须存在，且列全五个子目录** | 没有索引，`docs/` 会变成垃圾桶；评委翻不到东西等于没有 |
| **新增 `docs/` 子目录时，同一提交里更新索引** | 分开做，第二次一定忘 |

### 代码邻近文档的例外（不搬家）

这三种可以留在模块目录里，不强行收进 `docs/`：

1. 已存在且工具链约定的 `README.md`
2. 随代码生成的 API 文档 / 迁移说明 / 组件文档
3. 必须和本模块代码在同一次变更里维护的开发说明

**处理方式：不搬，只在 `docs/README.md` 加一条索引。**

### 什么时候更新哪一层

| 变了什么 | 更新哪 |
|---|---|
| 结构 / 方案 / 心智模型 | 对应层级的 `AGENTS.md`，或 `docs/architecture/` |
| 接口 / 字段 | `docs/contracts/`（唯一真相源）+ 受影响模块的 `AGENTS.md` |
| 只影响一个模块的实现细节 | `docs/modules/<模块>/` 或模块内 `README.md` |
| 进度 / 决策 / 坑 | `flow/`（不进 `docs/`） |

## 八、详规随项目（`flow/规范/`）

把本 skill 的 `references/` 复制进 `flow/规范/`。理由：**现场断网、换 Agent、换模型时，规则还在仓库里。**

**比赛版只复制当前阶段要用的 3–4 份**，不全量复制（全量 13 份会占掉仓库首屏，且没人读）：

| 阶段 | 复制哪几份 |
|---|---|
| S-1 / S0 | `13`（输入与赛道）、`08`（赛道与组队）、`01`（逆向） |
| S1 / S2 | `02`（调研）、`03`（论证） |
