# 10 · 发布与部署：让 demo 在别人的机器上也能跑

> 目标：演示那一刻，代码不在你的笔记本上，而在**一个评委能扫码打开、断电重启也不挂**的地方。
> **这条线 90% 的队伍死在"只在本地跑过"。**

---

## 一、先定死一件事：演示形态

部署方案由演示形态决定，先选形态再谈技术。

| 演示形态 | 需要部署什么 | 风险 | 适合 |
|---|---|---|---|
| **手机 App 现场装** | APK 直装 / TestFlight | 装不上、闪退、没网 | 消费级、硬件联动 |
| **手机 App 投屏** | 同上 + 投屏设备 | 分辨率不对 | 需要看细节 |
| **Web 大屏演示** | 静态站 + API | 会场网断 | 工具类、后台 |
| **硬件 + App** | App + 设备 + 云端 | 设备连不上 | 有硬件资源 |
| **纯 Agent / API** | 必须有可视化壳 | 看不见 = 0 分 | 不推荐裸演示 |

> **铁律：没有可视化界面，路演等于 0 分。** 纯后端 / Agent 项目必须配一个最简的 Web 壳（哪怕只是一个聊天框）。

---

## 二、赛前预埋：这些必须在 T-3 之前做完

到现场才做的，每一件都要 1–2 小时，且大概率失败。

| 项 | 具体做什么 | 判据 | 现场做的代价 |
|---|---|---|---|
| **服务器** | 开一台云主机（2C4G 够），装 Docker | `ssh` 能进，`docker ps` 正常 | 现场开机器要实名/审批 |
| **域名** | 短域名 + 已备案（国内）/ 免备案（海外） | 能在手机上打开 | 备案要 3–20 天，**没备案就别用国内主机** |
| **HTTPS** | Caddy 自动证书，或已有证书 | 浏览器显示小锁 | 没 HTTPS，摄像头/麦克风/地理位置全部不可用 |
| **安卓签名** | 生成 keystore **并备份到两处** | `assembleRelease` 成功 | **keystore 丢了就不能覆盖安装** |
| **iOS 证书** | 开发者账号 + profile + 设备 UDID | `Archive` 成功 | **现场配证书 = 弃赛** |
| **分发通道** | APK 放对象存储 / TestFlight 已上传过一版 | 扫码能下载 | — |
| **演示机** | 至少 2 台（1 主 1 备），同型号 | 已登录、已授权、电满 | 现场借不到同型号 |
| **大屏适配** | 1080p 和 4K 各试一次投屏 | 字能看清、不变形 | — |

### 一条经验

> **域名比服务器重要，签名比代码重要。**
> 服务器可以现场换，域名备案换不了；代码可以现场改，keystore 丢了那个 App 就永远不能更新。

## 三、安卓：编译 + 签名 + 分发

```bash
# 1. 打 release 包
./gradlew assembleRelease

# 2. 产物位置
app/build/outputs/apk/release/app-release.apk
```

`app/build.gradle.kts` 里签名配置：

```kotlin
android {
    signingConfigs {
        create("release") {
            storeFile = file("../keystore/release.jks")
            storePassword = System.getenv("KS_PASS") ?: ""
            keyAlias = "release"
            keyPassword = System.getenv("KEY_PASS") ?: ""
        }
    }
    buildTypes {
        release {
            signingConfig = signingConfigs.getByName("release")
            isMinifyEnabled = false   // 比赛别开混淆，出问题查不出来
        }
    }
}
```

### 三个必踩的坑

| 坑 | 症状 | 预防 |
|---|---|---|
| `minSdk` 高于演示机 | 装不上，报"应用未安装" | 演示机定下来后单独测一次 |
| `targetSdk` 过高 | 某些国产 ROM 权限申请异常 | 卡在 33 / 34，不要追最新 |
| 开了 R8 混淆 | 现场崩溃，堆栈是 `a.a.a` | `isMinifyEnabled = false` |

### 分发方式（按可靠性排序）

| 方式 | 时间 | 可靠性 | 备注 |
|---|---|---|---|
| 对象存储直链 + 二维码 | 10 min | 高 | 需要允许"未知来源安装" |
| 内网 HTTP 服务（同 WiFi） | 2 min | 中 | 会场 WiFi 一断就没了 |
| 蒲公英 / fir.im | 5 min | 中高 | 免费版有次数限制 |
| USB 线直装 | 1 min | 最高 | **但评委扫不到，只能自己演** |

**最优：对象存储直链做二维码（给评委扫）+ USB 直装（给自己演）**，两条都准备。

## 四、iOS：比安卓贵，也比安卓慢

### 先判断你有没有资格

| 情况 | 能做什么 | 时间成本 |
|---|---|---|
| 无开发者账号 | 只能**真机调试**（7 天有效期，需连电脑） | 低，但评委没法自己装 |
| 有个人开发者账号（$99） | AdHoc 分发（需提前登记设备 UDID）/ TestFlight | 中 |
| 有公司账号 | TestFlight 最顺 | 低 |

### 时间账（必须赛前算）

```
首次配证书 + profile          60–120 min
Archive + 上传 TestFlight     20–40 min
TestFlight 审核（外部测试）    1–24 h      ← 致命：比赛期间等不到
AdHoc 打包 + 分发             10–20 min
```

> **结论：24 小时比赛里，iOS 只有两条路——AdHoc（UDID 提前登记好）或模拟器录屏。TestFlight 别指望。**

### 兜底方案

iPhone 演示不了就**录屏 + 模拟器**。评委关心的是"功能对不对"，不是"你在我手机上装一遍"。
**提前录好 iOS 版操作视频**，比现场折腾签名划算得多。

## 五、Web 前端：三种部署，按时间选

| 方式 | 命令 / 操作 | 耗时 | 适合 |
|---|---|---|---|
| **Vercel / Netlify / Cloudflare Pages** | `git push` 或 `vercel --prod` | **5 min** | 静态站、Next.js、Vite |
| 服务器 + nginx 静态目录 | `scp -r dist/* root@ip:/var/www` | 15 min | 需要和 API 同域 |
| Docker compose 全栈 | `docker compose up -d` | 30 min | 前后端一起 |

### 一条判据

> **前端能上 Serverless 平台就上，不要自己配 nginx。** 省下的 20 分钟应该花在视频上。

**唯一例外**：需要和 API 同域才能免 CORS 时，用 nginx 反代 `/api`。

## 六、后端：单机 compose，别碰 k8s

```yaml
# infra/docker-compose.yml
services:
  api:
    build: ../api
    restart: always            # ★ 崩了自动起
    env_file: ../.env
    ports: ["8000:8000"]
    volumes: ["./logs:/app/logs"]
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8000/healthz"]
      interval: 30s

  web:
    image: caddy:alpine
    restart: always
    ports: ["80:80", "443:443"]
    volumes:
      - ../web/dist:/srv
      - ./Caddyfile:/etc/caddy/Caddyfile
      - caddy_data:/data
volumes:
  caddy_data:
```

`Caddyfile`（自动 HTTPS，比 nginx + certbot 少 20 分钟）：

```
demo.example.com {
    handle /api/* {
        reverse_proxy api:8000
    }
    handle {
        root * /srv
        try_files {path} /index.html
        file_server
    }
}
```

### 三条硬要求

| 要求 | 为什么 |
|---|---|
| `/healthz` 健康检查 | 现场能一眼看出"是服务挂了还是网络断了" |
| `restart: always` | 凌晨崩了没人管，早上演示就没了 |
| 日志落文件 | 现场排错靠日志，不靠猜 |

### 数据存储

| 选择 | 适用 | 不适用 |
|---|---|---|
| SQLite（挂卷） | **24h 首选** | 多实例 |
| 托管 PG（云厂商） | 需要多人同时读写 | 现场装 |
| 内存 / JSON 文件 | 纯 demo | 要展示"数据持久化" |

> **不要现场装数据库。** 装一次 40 分钟，且有 50% 概率因为权限/端口/字符集失败。

## 七、现场网络：最容易被忽略的一节

会场 WiFi 是所有 demo 的共同敌人。准备四层兜底：

| 风险 | 兜底 | 提前怎么准备 |
|---|---|---|
| WiFi 连不上 / 限速 | **手机热点** | 赛前测一次，确认能跑通全链路 |
| 公网 API 超时（大模型） | **预生成结果缓存**，按输入命中 | 赛前把 demo 会用的 10 组输入全部跑一遍存下来 |
| 服务器被墙 / 挂了 | **本机 docker 起一份，切 `localhost`** | 前端配置里留 `VITE_API_BASE` 开关 |
| 投屏分辨率不对 | 准备 1080p / 4K 两版页面 | 赛前投一次 |
| 会场断外网 | 全部服务本地化 | 静态站 + 本地 API + 本地模型（小模型） |

### 演示三件套（缺一不可）

```
① 真机实时演示    ← 主路径
② 本地备份服务    ← 网络挂了切 localhost
③ 2 分钟录屏      ← 上面两个都挂了放视频
```

**切换动作要提前演练。** 现场才发现"本地版没数据"，等于没有兜底。

## 八、时间节点：部署这条线的四个卡点

| 时间 | 做什么 | 判据 |
|---|---|---|
| **T-3** | 服务器 / 域名 / HTTPS / 签名全部就绪 | 能公网访问一个 "hello" |
| **F 点前** | 首次部署成功（用真实代码，不是 hello） | 演示链路在**演示环境**跑通一次 |
| **F 点后** | 重新部署一次，确认公网可访问 | 手机上能打开，且是 final 版本 |
| **演示前 1h** | 装到演示机，跑一遍，切一次兜底 | 主路径 + 兜底都验证过 |

> **注意：部署验证必须在"演示环境"，不是本机。** 本机 `localhost` 通了不等于公网通了——防火墙、端口、CORS、HTTPS 混合内容，四类问题只在公网出现。

## 九、发布检查清单（照抄进 `assets/materials/发布检查清单.md`）

交稿前逐项打勾，任何一项没过都不许上场：

- [ ] 后端 `/healthz` 返回 200
- [ ] 前端公网 HTTPS 可访问，无证书告警
- [ ] 手机 4G（不用会场 WiFi）能打开
- [ ] 安卓 APK 扫码可下载、可安装、可启动
- [ ] iOS 有可播放的录屏（或 AdHoc 已验证）
- [ ] 关键 API 在公网调用不超时（含跨域）
- [ ] 演示机已装好、已登录、电满
- [ ] 本地备份服务能起（断网可切）
- [ ] 2 分钟录屏已导出 mp4（不是工程文件）
- [ ] 二维码/短链已印在路演最后一页
- [ ] 索引了最后提交物：仓库、文档、视频、demo 链接
