# 交稿前机械检查（15 项，30 分钟做完）

> **这份清单只查"可机器验证"的错误，不查内容好坏。**
> 实测教训：一份决赛提交页，产品做得很扎实（四层架构、在线体验、34 页报告、11 页 PPT、全链路录屏），却同时犯了 6 个机械错误——**占位符源码链接 404、体验地址是内网 SIT、同一份文档里团队分工三处不一致、视频签名已过期、封面图引用别人的目录**。
>
> 这些错误跟产品能力完全无关，但每一个都在评委眼前。**内容再好，评委点开链接是 404，那一条就是 0 分。**

---

## 一、链接类（最容易致命，先查这类）

### 1. 每个外链都用手机 4G 点开一遍

**不能只用自己电脑点。** 电脑可能在公司网/VPN 里，手机 4G 才是评委的角度。

```bash
# 批量测状态码（在能上外网的机器上跑）
for u in <URL1> <URL2> <URL3>; do
  echo "$(curl -s -o /dev/null -m 20 -w '%{http_code}' -L "$u")  $u"
done
```

| 状态码 | 含义 | 处理 |
|---|---|---|
| 200 | 通 | — |
| 404 | 链接错 / 仓库没公开 | **必修** |
| 403 | 私有，需登录 | 改为公开，或提供免登录入口 |
| 401 | 需授权 | 同上 |
| 000 | **连不上**（DNS / 内网 / 超时） | **必修，见第 2 项** |

### 2. 域名解析出来的 IP 是内网地址吗

```bash
nslookup <你的体验地址域名>
```

**解析出 `10.x` / `172.16-31.x` / `192.168.x` = 内网环境，公网打不开。**

实测案例：`sit-p-xxxx.example.com`（某企业内网域名）解析到 **10.x.x.x**，公网 `curl` 返回 `000`。名字里的 `sit-`（System Integration Test）就是信号。

**处理**：至少准备一个公网可达的入口（正式域名 / 云服务器 / 内网穿透），或在提交页明确写"需在公司网络/VPN 下访问"——但**写在文档里不如给一个能打开的地址**。

### 3. 源码仓库是否为占位符

搜全文，确认没有：

```
example        /your-repo     /your-org
TODO           repository     placeholder
```

实测案例：`https://github.com/example/hackathon-meeting-notes` 返回 **404**，且仓库名 `hackathon-meeting-notes`（会议纪要）与产品毫无关系——说明是**从别人的模板复制过来没改**。

**所有链接必须用无痕窗口（未登录状态）打开一遍。**

原因：登录状态下你能看到自己的私有仓库、能看到自己 draft 的页面，**你会误以为所有人都能看到**。而且**私有仓库对无权限者返回 404，不是 403**——和"仓库不存在"看起来一模一样，评委会直接判定你没交。

| 情况 | 无痕窗口下会看到 |
|---|---|
| 公有仓库 | 正常打开 ✓ |
| 私有但没加评委 | **404**（看起来像不存在） |
| 私有且加了评委，但对方没接受邀请 | 404 |
| 占位符链接 | 404 |
| 仓库改过名 | 旧链接 404（GitHub 不留跳转） |

### 4. 带签名 / 带过期时间的 URL

图片和视频的 `src` 里如果出现：

```
?Expires=1792220213&OSSAccessKeyId=...&Signature=...
```

**`Expires` 是 Unix 时间戳，会在某个时刻失效。**

```bash
python -c "import datetime;print(datetime.datetime.fromtimestamp(1792220213))"
# → 2026-10-17 14:56:53
```

实测案例：文档 14:02 生成，签名 **14:56** 到期——**生成后 54 分钟视频就挂了**。如果桶是公开读还能播放，但你不能赌评委评审时桶还是公开的。

**处理**：换成不带签名的公开地址，或把视频打包进交付物。

### 5. 素材是否引用了别人的目录

看 `src` / `href` 里的路径段：

```
.../skill-assets/keaton_li/.../hackathon-cover.webp   ← 这是别人的账号
.../skill-assets/18708438791/...                       ← 这才是自己的
```

**引用他人目录的素材随时会失效**（对方清理、改名、删库）。实测案例里封面图就指向 `keaton_li`。

### 6. 相对路径的图片是否一起提交

如果 HTML 里是 `<img src="advantages.webp">` 这种相对路径，而你只提交了 `index.html`，**图全挂**。

**处理**：要么整目录打包（并说明点哪个文件），要么全部改外链，要么做单文件内联（base64）。

## 二、一致性类（不算错，但一眼看出"没通读"）

### 7. 同一份文档里，任何事实只允许有一种说法

把这几处并排放在一起核：

| 检查项 | 常见冲突 |
|---|---|
| **团队分工** | 基本信息表 vs 团队页卡片 vs 个人介绍，三处各写一套 |
| **项目名 / 队伍名** | 「智能客服助手」vs「客服小助手」vs 拼音缩写 |
| **数字口径** | 一处写"提升 42%"，另一处写"2.42%"（差 17 倍） |
| **完成度** | 一处说"已接入设备"，另一处说"真实设备执行仍在推进" |
| **联系方式** | 手机号 / 邮箱换了但只改了一处 |

**实测案例（最典型）**：同一份文档里，四位成员的分工出现三套说法——

| | 基本信息表 | 团队页卡片 | 个人介绍标题 |
|---|---|---|---|
| 甲 | 能源场景、产品方案 | AI 对话与决策翻译层 | 能源业务与产品验证 |
| 乙 | **数据工程、预测模型** | **前端与交互** | **算法优化与框架落地** |
| 丙 | 设备接入、控制下发 | 后台与执行 | 团队后端主要负责人 |
| 丁 | 数据管线、调度求解 | 算法与优化 | 市场研究与产品定位 |

**同一个人的三个身份互不相同。** 评委只要对照看两屏就会发现——而他不需要因此扣你技术分，他会开始怀疑其它内容。

### 8. 有没有别处项目的内容混进来

搜这几类词，逐个确认是否属于本项目：

```
车队 / 站点 / 单站 / 巡检 / 充电桩 / 交易 / 量化 / 回测收益
你的 KPI 语言：跑分 / 刷分 / 失分点 / 评测看板
```

实测案例：一个成员的介绍里出现「36 站车队三十天 +139.87%」「顾客实际只能跑到设备上限的四成三」「单站隔离」——这是**另一个充电站调度项目**的成绩，被贴进了德国户用储能的提交页。

**风险不只是跑题**：它把一个更强的数字放在一个身份错乱的位置，反而让那个数字变得不可信。

### 9. 内部语言是否漏到对外文档里

```
跑分 / 刷分 / 赛事跑分与质量度量     ← 对内说可以，对评委说像"专门刷分"
待定 / 待补 / 后续补充 / TBD
最佳 / 必交 / 选填                  ← 官方表单的字段名，不是文档标签
v1 / v2 / 终版 / 真的终版
```

有一条要单独说：**"负责赛事跑分与质量度量"这种职责描述，评委看到会怎么想？** 他可能理解成"你们有个人专门研究怎么拿分"，而不是"你们做了一套评测看板"。**把内部角色翻译成外部语言**：`质量度量与回归验证`。

### 10. 产品名、赛道名与官方写法一致

官方报名表写的是"充电储能"，你文档里就不能写"储能赛道"。**这类不一致不算错，但会让评委以为你报错了赛道。**

## 三、数字类

### 11. 每个收益数字都有基线

| 写法 | 判据 |
|---|---|
| "提升 124.17%" | ❌ 相对什么？没有基线 |
| "相对自发自用基线 +2.42%" | ✅ 有基线、有口径、有单位 |
| "官方分 +137.62%" | ⚠️ 有基线（官方分），**但没有换成钱** |

**判据**：一个不懂你项目的评委，能不能用一句话复述这个数字的含义？不能就重写。

### 12. 分数与钱不要混着用

如果预赛文档写的是「七日 +2.43 欧元 / +2.42%」，决赛文档就不要退回到「官方分 +137.62%」——**后者评委算不出值多少钱**。

**处理**：两个都给。「+137.62% 官方分（折算七日净费用 −X 欧，对照基线 Y 欧）」。

### 13. 声称的完成度与可验证范围一致

搜这些词，逐个确认后面有没有限定：

```
已实现 / 已接入 / 已支持 / 全链路 / 端到端
```

实测案例：文档一方面写「证据分层陈述，合成设备回放与模拟场次不能外推为真实家庭收益」（很好），另一方面又把模拟场次的收益当成主结果展示（矛盾）。

**判据**：把每个"已"字后面接的名词，拿到问答里问一遍——"评委现在点开能看到它吗？"答不上就改成"计划中/部分开放"。

## 四、收尾类

### 14. 文本里没有残留的编辑痕迹

搜：

```
<span> 以外的：<TODO>  <!--  -->  批注  待确认  张三说
"参考模板"  "示例"  "lorem"
```

### 15. 整页在手机上看一遍

评委大概率用手机点开链接。检查：

- [ ] 横向不出现滚动条（表格 / 代码块最容易溢出）
- [ ] 字号在手机上不用放大就能读
- [ ] 视频在手机上能播放（不是只有桌面能播）
- [ ] 图片不是 8MB 原图（加载 10 秒等于没看）
- [ ] 折叠/展开的交互在触摸下正常

## 五、执行顺序（30 分钟）

| 顺序 | 做什么 | 耗时 | 为什么排这个位置 |
|---|---|---|---|
| 1 | 跑第 1–6 项（全是命令行/搜索，能批量做） | 10 min | **致命级，且能自动化** |
| 2 | 跑第 7–10 项（一致性） | 10 min | 需要人眼对照，但检查表能兜住 |
| 3 | 跑第 11–13 项（数字） | 5 min | 只需看有没有基线 |
| 4 | 跑第 14–15 项（收尾） | 5 min | 手机实测一遍就够 |

**只做第 1 项也能救回大半。** 如果只剩 5 分钟，就做第 1、2 项——链接能不能打开，是唯一"归零"级别的错误。
