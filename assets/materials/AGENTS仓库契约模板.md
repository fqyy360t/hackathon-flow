# AGENTS.md 仓库契约模板（24 小时最小内核）

> 用途：多人 + 多 Agent 同时改一个仓库时，**上下文契约**比模型能力更决定成败。
> 24h 版只保留 6 个文件。完整体系（两周以上项目）见方法论附录 B。

---

## 一、6 个文件

```
AGENTS.md              运行时合同：谁在推进、当前阶段、禁改项
flow/进展.md           顶部一条"交接棒"，字段固定
flow/decisions.md      已定的决策 + 理由（不回滚，除非写明为什么）
docs/contracts/         数据结构 / 接口 / 字段的唯一来源
flow/assumptions.md     ⬜未知 与 🟠弱推测 全部登记，禁止写死在代码里
docs/红线.md           不能碰的东西（真实设备、账号、时限、主办方数据）
```

---

## 二、AGENTS.md 骨架（直接复制改）

```markdown
# 项目：<名称>
阶段：S4 构建（24h）｜最后更新：<时间>

## 现在在做什么
<一句话>。当前卡点：<一句话>。

## 谁负责什么
- <人A>：<交付物>｜目录 `src/app/`
- <人B>：<交付物>｜目录 `src/model/`
- 公用只读包：`shared/`（**任何人不得修改**）
- 接口真相源：`docs/contracts/`（只有 <接口负责人> 有写权）

## 铁律
1. 契约只在 `docs/contracts/`，本文件不复制正文（复制必然版本漂移）。
2. 任何"未知"必须登记到 `flow/assumptions.md`，不允许凭猜测写死接口。
3. F 点（提交 − 7h）后冻结功能，只修 bug。
4. 改动真实设备/账号前，先在 `flow/decisions.md` 记录并得到确认。

## 命名与目录
- 每人一个顶层目录，互不改对方文件。
- 每人一个**模块目录**（`web/` `api/` `android/` …），模块内自行组织，不跨目录改文件。
- 公共工具放 `shared/`，改动需在 decisions 里留一条。

## 完成定义
回归零失败 + 三级验证（dry_run → 小窗口真机 → 长窗）+ 文档与台账同步。
"代码能跑"不算完成。
```

---

## 三、flow/进展.md 的"交接棒"（字段固定）

```markdown
## 交接棒 · <时间>
- 已完成：<可验收的结果，不是"做了 XX 模块">
- 当前状态：<能跑 / 半通 / 卡住>，卡在 <具体现象>
- 证据：<日志片段 / 截图路径 / 复现步骤>
- 下一步建议：<1–3 条>
- **未决事项（待用户决策）**：<必须写成"需要人拍板的选择"，不要写"下一步">
```

> 最后一项写成"未决事项"，下一个 Agent 会停下来问；写成"下一步"，它会自行推进。

---

## 四、假设台账（防止在假接口上写一天代码）

| ID | 假设内容 | 置信度 | 依据 | 若为假，影响 | 何时验证 |
|---|---|---|---|---|---|
| H1 | 设备支持推送画面 | 🟡 | 官方文档有描述 | 整条链路重做 | 1h 内真机试 |
| H2 | 模型返回 JSON 可解析 | ✅ | 实测 3 次 | — | — |

置信度四级：✅实证（可引行号）/ 🟡强推测（有旁证，必留替换点）/ 🟠弱推测（不进契约）/ ⬜未知（只登记）。

---

## 五、协作现实检查

- 若 git push 需要 > 5 分钟 → **放弃分支协作，改同机开发**（工具链按 24 小时真实成本重算）。
- 若 hook / 自动化依赖的组件缺失（如没装 jq）→ 纪律只能靠手动，**明确写进 AGENTS.md 让所有人知道**。
- 每个 Agent 都必须知道自己**不做什么**（负范围）。三个 Agent 都写清边界，是防止互相覆盖的唯一有效手段。
