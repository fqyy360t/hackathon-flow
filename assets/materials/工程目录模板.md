# 工程目录模板（模块化 monorepo）

> 用法：按这个结构建目录，**删掉用不到的模块**。判据：新增一个端时，不需要改现有结构。
> 生长顺序：**第 1 天**只建 `flow/` `docs/`；**G1 之后才建模块目录**；S3 才建脚手架。
> 详规：`references/09-工程管理.md`

## 目录

```
<项目>/
├── AGENTS.md                  根级运行时合同（唯一）
├── CLAUDE.md -> AGENTS.md
├── .hooks/ .claude/ .codex/   收工自检（只装根目录）
│
├── flow/                      唯一控制层
│   ├── charter.md  team.md  未认领.md
│   ├── plan.md  claims.md  assumptions.md
│   ├── 进展.md  decisions.md  踩坑记录.md
│   ├── tasks/D0X-*.md
│   └── 规范/
│
├── docs/                      集中内容层
│   ├── README.md              索引（必须）
│   ├── product/               赛程卡 赛道盘点 产品与功能清单 证据表 预赛材料
│   ├── architecture/          项目结构 评分映射表 契约冻结
│   ├── contracts/             ★ 接口唯一真相源
│   ├── modules/<模块>/
│   └── reviews/            跨模型评审 + 复盘.md（赛后 48h）
│
├── web/        AGENTS.md  CLAUDE.md        ← G1 后按形态建，不是全建
├── android/    AGENTS.md  CLAUDE.md
├── ios/        AGENTS.md  CLAUDE.md
├── api/        AGENTS.md  CLAUDE.md
├── ml/         AGENTS.md  CLAUDE.md        离线部分，不进部署
│
├── shared/                    代码共享物（生成的类型 / 常量），不定义契约
├── infra/
│   ├── docker-compose.yml
│   ├── Caddyfile
│   └── deploy.sh
└── scripts/
    ├── dev.sh
    ├── check.sh
    └── build.sh
```

**模块取舍：**

| 形态 | 建哪些 | 不建 |
|---|---|---|
| Web 工具 | `web/` `api/` | android ios ml |
| 手机 App | `android/` `api/` | web ios ml |
| 硬件 + App | 固件目录 `android/` `api/` | web ios |
| 纯 Agent / API | `api/` + `web/`（最简壳） | android ios ml |

> **空文件夹是负分。** 评委翻仓库看到 `ios/.gitkeep`，会判断你不知道要做什么。

## docs/contracts/ 的最小内容

`docs/contracts/api.yaml`（只写 demo 用到的 6–8 个接口）：

```yaml
openapi: 3.0.0
info: { title: <项目> API, version: 0.1.0 }
paths:
  /api/healthz:
    get: { summary: 健康检查, responses: { "200": { description: ok } } }
  /api/<主接口>:
    post:
      summary: <一句话>
      requestBody:
        content:
          application/json:
            schema:
              $ref: "#/components/schemas/AskRequest"
      responses:
        "200": { description: 成功 }
        "422": { description: 输入无效 }
components:
  schemas:
    AskRequest:
      type: object
      required: [query]
      properties:
        query: { type: string }
        top_k: { type: integer, default: 5 }
```

## fixtures 四类状态（每个接口都要有）

```
docs/contracts/fixtures/<接口名>/
├── success.json         正常返回
├── empty.json           合法但无结果
├── no_coverage.json     超出能力范围（对应 UNKNOWN）
└── error.json           服务端错误
```

每份都带 `_meta`：

```json
{
  "_meta": { "owner": "甲", "updated": "2026-10-27T03:20:00Z" },
  "items": []
}
```

> **前端在接口没实现前直接读 fixtures 开发**，这一条把"等后端"清零。

## 五条格式约定（开工第一小时定死，写进 `docs/architecture/契约冻结.md`）

| 项 | 选定值 |
|---|---|
| 命名风格 | `snake_case` / `camelCase` |
| 时间格式 | **ISO 8601 UTC 带时区**（`2026-10-27T03:20:00Z`） |
| ID 类型 | **一律 string** |
| 空值表示 | **一律 null** |
| 分页结构 | `{ items, total, cursor }` |

## 三条脚本（新队友 5 分钟内能跑起来）

`scripts/dev.sh`

```bash
#!/usr/bin/env bash
set -e
test -f .env || { echo "缺 .env，从 .env.example 复制"; exit 1; }
(cd api && uvicorn main:app --reload --port 8000) &
(cd web && npm run dev) &
wait
```

`scripts/check.sh`

```bash
#!/usr/bin/env bash
set -e
curl -sf http://localhost:8000/api/healthz > /dev/null || { echo "API 没起来"; exit 1; }
python scripts/check_claims.py     # 跑 flow/claims.md 的断言
```

`scripts/build.sh`

```bash
#!/usr/bin/env bash
set -e
(cd web && npm run build)                 # → web/dist
(cd android && ./gradlew assembleRelease) # → app-release.apk
docker compose -f infra/docker-compose.yml build
```

## 模块级 AGENTS.md

用 `assets/MODULE_AGENTS.md` 生成，只写三件事：

```markdown
# <模块名>

负责：<一句话>
不负责：<明确不属于本模块的范围>

## 怎么跑
<命令>

## 不许做
- 不另起计划（计划在根级 flow/plan.md）
- 不改 docs/contracts/（只有 <人名> 有写权）
- 不提交 .env / 密钥

根级合同：../AGENTS.md
```

`CLAUDE.md` 复制一份（Windows 不软链）。改完 `AGENTS.md` 立刻 `cp AGENTS.md CLAUDE.md`。
