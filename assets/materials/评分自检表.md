# 评分自检表（交稿前 20 分钟逐项打勾）

> 用途：按官方四项评分 + 团队匹配逐条自检。**任一项打 0，先修它再交。**

## 一、选题明确度（25 分）

| # | 检查项 | 是/否 | 证据位置 |
|---|---|---|---|
| 1 | 第一段明确写出"我们对赛题的理解：___，而不是 ___" | | |
| 2 | 写清了赛道的**核心矛盾**（不是罗列现象） | | |
| 3 | 目标用户具体到"谁会为什么付钱"，不是"所有用户" | | |
| 4 | 痛点有**真实差评/工单原文**支撑（≥ 3 条） | | |
| 5 | 主动写明"我们放弃了哪几个痛点，为什么" | | |

## 二、方案清晰度（25 分）

| # | 检查项 | 是/否 |
|---|---|---|
| 6 | 解决方案能用一句话说清（把 ___ 从 ___ 变成 ___） | |
| 7 | 核心功能 ≤ 3 个，每个都答出"做什么 / 怎么做 / **为什么这样做**" | |
| 8 | 有一个结构化字段表或状态机（不是模糊的"AI 自动处理"） | |
| 9 | 画了 1 张架构/流程图（不是装饰图） | |
| 10 | 技术路径能指到具体组件，不是"用大模型" | |

## 三、项目创新性（25 分）

| # | 检查项 | 是/否 |
|---|---|---|
| 11 | 有一句"不是……而是……"的差异化对照 | |
| 12 | 创新点落在**需求/机制**层，不只是"用了新模型" | |
| 13 | 能指出竞品的具体失败点（来自竞品差评） | |
| 14 | 体现 AI Native：AI 承担的是"编译/决策/维护状态"，不是"套个对话壳" | |

## 四、落地可行性（25 分）

| # | 检查项 | 是/否 |
|---|---|---|
| 15 | 有"24 小时后评委可亲眼验证的 N 件事"清单 | |
| 16 | 每件事都是**现象级**描述（动一下设备，界面变），不是功能名 | |
| 17 | 有降级方案 / 兜底路径 | |
| 18 | 明确写了"不提前编结果，用 demo 现场验证" | |
| 19 | 团队分工与人手匹配（4 人 = 4 个可验收输出） | |

## 五、团队能力匹配（附加分）

| # | 检查项 | 是/否 |
|---|---|---|
| 20 | 每人背景一句话，直接对上方案所需能力 | |
| 21 | 附了过往作品链接 | |

## 六、证据纪律（评委会追问的）

| # | 检查项 | 是/否 |
|---|---|---|
| 22 | 每个数字有（来源，年份） | |
| 23 | 每个关键结论有"不能用它证明什么" | |
| 24 | 没有"预计千亿市场"式的无源数字 | |
| 25 | 主动列出了 1 条最强反例，并说明应对 | |

---

## 打分换算

- **23 项以上打勾**：可以交。
- **18–22**：补齐"为什么这样做"和"可验证清单"再交。
- **18 以下**：不要交，回去做 S0 逆向 —— 你不是写得不好，是还没想清打哪个格子。
