# 评分映射表

> **这张表的作用：让评分表在任何时刻到达，都只需要 30 分钟重对齐，而不是 3 小时重写。**
> 建立时机：开赛即建（可先空着评分项一列）。每次评分表刷新，更新一版，追加不改旧版。
> 颗粒度要求：**到内容单元**（一张功能卡 / 一条证据 / 一张表），不到章节。章节太粗，判断不出砍哪段。

## 二、内容单元清单

> 每写一个新内容单元，立刻加一行。不要事后补。
> **"服务项"分预赛 / 决赛两栏**——同一个内容单元在两边可能对应不同项（预赛看论证严谨，决赛看一眼看懂）。

| ID | 内容单元 | 在哪（文件 § 位置） | 服务项（预赛） | 服务项（决赛） | 证据强度 | 可摘出？ |
|---|---|---|---|---|---|---|
| C01 | | | | | A/B/C/D | ✅ / ⚠️ / ❌ |
| C02 | | | | | | |
| C03 | | | | | | |

**证据强度**（沿用证据五级阶梯，取最低那一级）：

| 级 | 含义 |
|---|---|
| **A** | 一手原文（差评截图 / 工单 / 官方文档原文 / 真机日志） |
| **B** | 公开数据推算（官方统计 + 自己算） |
| **C** | 条件模型计算（假设明确、可复算） |
| **D** | 团队判断 / 类比推测（无外部依据） |

**可摘出？** 这一列决定重排成本：
- ✅ 能独立成段发给别人看懂 → 可自由重排、可单独上幻灯
- ⚠️ 依赖上下文才成立（如长推导中的一步）→ 重排需补一句过渡
- ❌ 耦在长文里，摘出就断 → **这是要改写的信号，越早越好**

## 三、三个差集（每次评分表刷新后重算一次）

### 3.1 缺口：有评分项，没内容

| 评分项 | 权重 | 现有证据强度 | 缺口严重度 | 处理（L1换说法 / L2换顺序 / L3换功能 / 放弃） |
|---|---|---|---|---|
| | | 无 | 高 | |
| | | | | |

**严重度判据**：
- **高** = 权重前二 + 完全无内容 → 走 G3.5，或明确放弃
- **中** = 权重前二 + 有内容但 D 级证据 → 升级证据
- **低** = 权重后三 → 不动

### 3.2 冗余：有内容，不服务任何评分项

| 内容单元 | 花了多少时间 | 砍了会损失什么 | 处理 |
|---|---|---|---|
| | | | 砍 / 降为附录 / 不演示 |

**先算这一栏。** 砍冗余省下的时间正好用来补缺口——这是总分不变时唯一"净赚"的操作。

### 3.3 薄弱：高权重项只有弱证据

| 评分项 | 现有最强证据 | 能否用已有素材升级 | 升级需要多久 |
|---|---|---|---|
| | | 有原始链接？有原始日志？找得到用户？ | |

**判据**：升级一条证据（D→A）比新增三条内容更值钱。

## 五、封口检查（每次重对齐结束必须过）

- [ ] 评分表原文已贴进 `flow/decisions.md`
- [ ] 三个差集已算出数字（不是"感觉差不多"）
- [ ] 放弃的项已写明，且现场问答不主动提
- [ ] 全队已被口头告知"哪一项不再讨论"

## 六、如果到 O 点还没拿到评分表

按**形态 B（等权假设）** 继续推进，并在本表顶部记一句：

```
评分表未到 · 按四项等权 + AJ 五条通用判据推进 · 追问日期 ___
```
