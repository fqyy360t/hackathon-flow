# docs 索引

> **这个文件必须存在，且必须列全五个子目录。** 没有索引，`docs/` 会变成垃圾桶；评委翻不到东西等于没有。
> 规则：**新增子目录时，在同一个提交里更新本文件。** 分开做，第二次一定忘。
> 进度、决策、交接**不进这里** → 去根级 `flow/`。

## product/ — 要做什么、为什么

| 文件 | 内容 | 主要读者 |
|---|---|---|
| `赛程卡.md` | 报名 / 提交截止 / F 点 / 时长 / 人数规则 / 提交入口 | 全队 |
| `赛道盘点.md` | 主办方动机 + 所有赛道评分 + 人数技能反推 | 队长 |
| `产品与功能清单.md` | 形态 + P0/P1/P2 + 功能卡 | 全队 |
| `证据表.md` | 差评原文 / 工单 / 访谈，带来源与边界 | 写材料的人、评委 |
| `预赛材料.md` | 预赛文档定稿（L 档 ≈ T-8；无预赛则不建） | 评委 |
| `密钥清单.md` | 谁申请的 / 有效期 / 额度 / 谁能用 | 主程 |

## architecture/ — 怎么搭、怎么对上评分

| 文件 | 内容 | 什么时候写 |
|---|---|---|
| `项目结构.md` | **七段**：架构图 / 目录职责 / 选型理由（带代价）/ 主链路（标文件行号）/ 三条决策（含被否决方案）/ 怎么跑怎么验 / 已知边界 | A-2 写 §二 §三 骨架；S3 每条决策加一条；S5 补 §一 §四 §七 |
| `评分映射表.md` | 内容单元 → 服务哪个评分项 → 证据强度 ABCD | 第 1 天建，评分项留空 |
| `打分记录.md` | 每次打分的六维分 + **扣分条目** + 与上一轮的差；无评分卡时标"模拟分"，不出加权总分 | T-10 / F 点前 2h / 材料冻结前 / 评分卡到达时各追加一段 |
| `契约冻结.md` | G2 产出物：范围 / 三条固定查询 / 四类状态样例 / ID 统一 | G2 |

> `项目结构.md` 模板在 `assets/docs/项目结构.md`，写法见 `references/15-项目结构与提交整理.md`。
> **它不是 README 的长版**：README 给评委 30 秒扫，这份给要跑起来的人读 10 分钟。两份必须分开。

## contracts/ — 跨模块的唯一真相源

| 路径 | 内容 |
|---|---|
| `api.yaml`（或 `types.ts`） | 本次 demo 用到的 6–8 个接口 |
| `字段命名.md` | 命名风格 / 时间格式 / ID 类型 / 空值 / 分页，一次定死 |
| `fixtures/success.json` | 正常返回 |
| `fixtures/empty.json` | 空结果 |
| `fixtures/error.json` | 错误 |
| `fixtures/no_coverage.json` | 无覆盖 |

> **代码里不二次定义。** 需要 import 就从这里生成到 `shared/`。两份定义必然漂移，而漂移是在第 18 小时发现的。

## modules/ — 只影响一个模块的说明

| 目录 | 内容 |
|---|---|
| `modules/<模块名>/` | 该模块的内部约定、禁区和踩坑；跨模块的写 `contracts/` |

> 已有的模块 `README.md`、随代码生成的文档可以留在模块目录里，**不搬家**，在这里加一条索引即可。

## reviews/ — 评审记录 + 赛后复盘

| 文件 | 内容 |
|---|---|
| `reviews/<日期>-<对象>.md` | PASS / FAIL + 理由 + 审稿模型名 |
| `reviews/复盘.md` | **四层**：事实（只有时刻和数字）/ 归因（判断错 vs 执行差）/ 可复用（A/B/C 三档）/ 反哺（改了 skill 哪里）。赛后 48h 内写完 |

> 复盘模板在 `assets/docs/复盘.md`，写法见 `references/16-赛后复盘与资产化.md`。
